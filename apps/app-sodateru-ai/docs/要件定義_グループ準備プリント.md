# 要件定義：育てるAI グループ準備プリント作成機能（APP006 追加機能）

2026-09-26 作成。実装の正本。

## 0. 前提・位置づけ
- 育てるAI（`apps/app-sodateru-ai`）の教員向けページとして追加する（独立アプリにはしない）。教材データ・単元ID・教員認証を共有する。
- 本機能ではサーバ側から LLM API（Gemini 等）を一切呼ばない。プリントの中身は教員が契約しているサブスクAI（ChatGPT / Gemini / Claude など）で作り、アプリは「材料を書き出す」「返ってきた結果を取り込んでレイアウトする」だけを担当する（API料金ゼロ）。
- UI文言・コメントは日本語。

## 1. 授業での使い方
1. 4〜5人のグループ（1クラス8〜10グループ）が、本プリントで問題を解き、ルールを言葉でまとめ、互いに確認する。
2. グループでプリントを見ながら育てるAI（ソウタ）に文法を教える。
3. 育てるAIのテストスコアをクラス内のグループ同士で競う。

→ プリントは「問題に答える」だけでなく「文法を言葉で説明できる」ようにする誘導質問を中心にする。

## 2. 画面と操作フロー（`/teacher/worksheet`、教員のみ）
- 教員ダッシュボードからリンクする。
- STEP 1 対象を選ぶ: 単元（`UNIT_CATALOG`）、知識項目（初期値は全部オン）、確認問題の数（初期値8、4〜12）、難易度の目安（基礎寄り／標準）。
- STEP 2 材料をコピー（TSV、4章）／システムプロンプトをコピー（5章）。手順を3行で表示。
- STEP 3 AIの出力を貼り付け→取り込み。検証エラーは日本語で一覧表示。修正して再取り込み可。
- STEP 4 A4縦プレビュー。「生徒用のみ」／「生徒用＋解答ページ」切替。印刷ボタン（`window.print()`）。
- 取り込み結果は単元ごとに localStorage に保存・復元（失敗しても動く）。DB 保存はしない。

## 3. 使う教材データ
- 正本 `curriculum/data/g24_curriculum.json`。実行時は `curriculum/generated/g24-runtime.json` と、生成スクリプトが出力する `curriculum/generated/worksheet-knowledge.json`（見分け方 decisionCriteria・よくある誤解 commonMisconceptions・単元コード）を使う。
- **`eligibility: "assessment"` の問題は絶対に書き出さない**（育てるAIのテストに出る問題のため）。書き出すのは practice のみ。
- 教材JSONはクライアントのバンドルに入れない。教員専用 API `GET /api/teacher/worksheet/[unitId]` で必要なフィールドだけ返す。

## 4. 書き出し形式（アプリ → サブスクAI）
- タブ区切り。先頭 `#SODATERU_WORKSHEET_REQUEST	v1`、末尾 `#END`。行頭の種別列（META / KNOWLEDGE / PRACTICE）で行を区別。セル内のタブ・改行は半角スペースに置換。
- PRACTICE は選択した知識項目の practice 問題から、項目ごとに偏らないよう最大「確認問題の数×2」問。
- 問題の選び方は決定的（単元ID＋選択項目からシード）。

## 5. サブスクAI用システムプロンプト（`lib/worksheet/system-prompt.ts`、版番号付き）
- 役割、入力形式、KNOWLEDGE 外の文法を扱わない、確認問題は PRACTICE をそのまま使う（不足時のみ新規作成し `source: "new"`）、誘導質問は「ルールを言葉で説明させる」形、「ソウタの間違いを直そう」は commonMisconceptions を元にする、出力は6章の JSON だけを ```json ブロック1つで返す、文字数上限を守る。

## 6. 取り込み形式（サブスクAI → アプリ）と検証
- JSON（コードブロック記号や前後の余計な文は自動除去）。項目: format, version, unitId, title, goal, checkQuestions[], ruleQuestions[], fixSouta[], exampleTasks[], teachingPlan{keywords, orderHint}（詳細は `lib/worksheet/schema.ts`）。
- 検証: format/version/unitId 一致、knowledgeId が選択項目内、選択肢ちょうど4つ・A〜D重複なし・answer が選択肢内、bank 問題は practice に実在し正解一致（不一致なら教材JSONを正として警告）、**assessment 問題の ID は取り込み拒否**、文字数超過は警告、件数（確認問題4〜12、ルール質問は選択項目1つにつき1〜2、ソウタ2〜4、例文1〜3）。

## 7. プリントのレイアウト（A4縦、生徒用は原則2ページ以内）
- ヘッダー: 単元名／年 組／グループ番号／メンバー氏名欄5人分／今日のゴール
- Part 1 確認問題（4択・答え欄・決め手欄）
- Part 2 ルールを言葉にしよう（誘導質問・ヒント・記入欄3行）
- Part 3 ソウタの間違いを直そう（吹き出し・記入欄）
- Part 4 教えるための例文を作ろう
- Part 5 ソウタに教える作戦メモ（キーワードのチェック欄、教える順番、30字以内で説明）
- 解答ページ（切替時のみ、改ページ）
- `@page { size: A4 portrait; margin: 12mm }`、Part 途中で改ページしない、モノクロで読める。

## 8. 非機能要件
- LLM API 呼び出しなし・DB 変更なし。生徒の個人情報を扱わない。教員以外は API・ページとも拒否。

## 9. 受け入れ基準
- lint / typecheck / build:vinext が通る。
- 書き出した TSV に assessment 問題の ID が含まれないことをテストで確認。
- 壊れた JSON、単元違い、正解ラベル誤り、assessment ID 混入で日本語エラーが出て取り込まれない。
- 印刷プレビューで Part の途中で改ページされない。

## 10. 今回やらないこと
- グループ単位のログイン・グループ対抗ランキング／アプリ内での LLM 生成／プリント内容の DB 保存／Word・PDF 書き出し（ブラウザの「PDFに保存」で代用）
